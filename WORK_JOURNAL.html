01

專案概況

這是一套以《Star Trek》LCARS 為視覺基礎的個人資訊管理網站，將日常工作、財務、娛樂紀錄、天氣及太空資訊整合在同一個控制台介面。

Application Type原生靜態單頁網站
TechnologyHTML / CSS / JavaScript
Build Process無框架、無建置工具
Main Entryindex.html
Feature Scriptsjs/ 共 11 個檔案
Current Status長期維護／持續開發

目前介面已形成穩定設計語言，後續開發應保留現有導覽、版面配置與操作習慣，以小範圍修改逐步完成尚未實作的功能。

03

系統架構

介面層index.html
頁面骨架、全部 CSS、SVG 圖示與響應式配置
核心協調層js/core.js
語言、主題、導覽、快取、工具與初始化流程
功能模組層js/*.js
專案、出勤、財務、比分、媒體、天氣、太空及便箋
資料服務層Apps Script、Google Sheets、外部 API、localStorage 與 sessionStorage
  • 網站沒有前端框架、套件管理或編譯步驟，直接開啟 index.html 即可執行。
  • 所有 JavaScript 都是傳統腳本，共用全域作用域；載入順序及函式名稱具有相依性。
  • core.js 提供 t()、beep()、cacheGet()、cacheSet() 與主頁切換等共用能力。
  • switchPage() 依 .page[data-page] 與 .tab-btn[data-tab] 切換頁面，沒有 URL router；次級分頁分別由 setWsSubtab()、setLibSubtab()、setObsSubtab() 與 setFinanceTab() 控制。
  • 事件處理混用 HTML inline handler、元素的 onclick 及 addEventListener()，調整 selector 前需搜尋所有呼叫位置。
  • scores.js 的 escapeHtml()／escapeAttr() 被媒體模組使用；notes.js 的 overlay、prompt 與 confirm 被多個模組共用。
  • project.js 另有同名 closeOverlay()，會在淡出後呼叫 notes.js 留下的 window._overlayClose；不能將其中一個版本直接當成無用重複程式刪除。
  • 出勤模組沿用 proj-modal-* 樣式；影集、電影、閱讀共用 lib-* 樣式。調整共用 CSS 時需檢查所有使用端。
  • 啟動時會抓取金融、比分、排名及首頁天氣，其他資料部分按頁面造訪延遲讀取；比分計時器目前不會因離開 SCORES 頁面而停止。
  • 圖片資產集中在 images/posters/，歷史版本壓縮檔放在 _versions/。
腳本載入順序： finance → scores → notes → library → films → reading → attendance → project → weather → space → Astronomy Engine → core。
04

功能特色

MAIN · 主控台

日期時間、台北天氣摘要、系統運行時間、分類捷徑、Captain's Log、計算機、計時器與語音狀態。

WORKSPACE · 工作區

以 Project → Milestone → Task 管理專案，提供看板、優先順序、期限、模板；另有休假與加班紀錄。

FINANCE · 財務

顯示台美股、基金與匯率，支援自訂投資分頁、持倉資料、資產配置堆疊圖與 treemap。

SCORES · 賽事

讀取 MLB 比分與排名，預設聚焦 Baltimore Orioles，包含逐局資訊、賽況與自動更新。

LIBRARY · 媒體庫

記錄影集季／集進度、電影與重看、書籍閱讀與評分，提供搜尋、篩選及本機海報。

OBSERVATORY · 觀測站

台灣縣市天氣、逐時與逐日預報、日照資訊，以及 NASA APOD、行星軌道與 Voyager 顯示。

NOTES · 全站便箋

右側便箋跨頁顯示，支援排序、顏色及到期提醒；資料保存在目前瀏覽器。

LCARS UI

深色控制台、彎肘框架、膠囊按鈕、掃描線、SVG 圖示、三種主題及中英文切換。

RESPONSIVE

桌面使用左側導覽、中央內容與右側便箋三欄；900px 以下調整為單欄流程。

Apps Script 的 GET 用於讀取，POST 多半以 text/plain 傳送 JSON，並以 action 指定操作。端點直接寫在前端，但 repository 沒有後端程式、資料表 schema、部署或權限設定，因此無法只靠前端確認伺服器驗證及真實資料狀態。瀏覽器儲存也綁定 origin；若改用不同 hostname、port 或開啟方式，看到的 localStorage／sessionStorage 可能不同。

設計與維護原則

開始工作前

  1. 先閱讀本工作手記。
  2. 查看專案目錄與 git status。
  3. 必要時查看最近的 git log 與相關 commit。
  4. 若有 HANDOFF.md 或 TODO.md，先閱讀再修改。
  5. 若其他電腦最近有新修改，先理解變更內容。

程式修改

  • 採取最小必要變更，優先修改現有檔案。
  • 不任意更換框架、函式庫或建置方式。
  • 不新增不必要的相依套件。
  • 修改函式前先確認所有呼叫位置。
  • 範圍外的舊問題先記錄，不順手大改。

UI / UX

  • 未經明確要求，不改變頁面配置、操作流程、導覽方式、按鈕位置或響應式行為。
  • 沿用現有 LCARS 設計語言及命名。
  • 桌機與手機版須交叉檢查。
  • 跨頁調整前先確認共用元件與共用樣式。

JavaScript

  • 先找出事件監聽、DOM selector、共用函式、資料來源及瀏覽器儲存。
  • 不任意重新命名函式、DOM ID 或 class。
  • 新增功能應整合進現有架構，避免平行重複邏輯。
  • 資料格式變更須同步檢查讀寫及所有使用端。

CSS

  • 優先修改現有 class，避免大量重複樣式。
  • 注意 selector specificity。
  • 沿用既有 responsive breakpoint。
  • 不為單一畫面問題大量使用 !important。

Git 與檔案安全

  • 保留未提交修改，不覆蓋或丟棄使用者內容。
  • 未經明確要求，不執行 commit、push、pull、merge、rebase、reset，亦不建立或切換 branch。
  • 不刪除用途未確認的檔案或大量既有程式碼。
  • 不因程式可以更漂亮而重做整個網站。
核心原則：先理解現有專案，再修改；優先維持既有功能與使用者操作方式；採用最小必要變更，避免非必要重構。

完成工作後的固定回報

  1. 修改了哪些檔案，以及每個檔案的主要變更。
  2. 是否可能影響其他功能或共用元件。
  3. 建議使用者測試哪些項目。
  4. 若適合，提供簡潔明確的 Git commit message，但不自行提交。
  5. 在本頁更新紀錄留下日期、行為變更、影響範圍與驗證結果。

後續開發方向

第一階段 · 穩定性

驗證初始化流程、子分頁還原、重複請求及共用彈窗生命週期。

第二階段 · 資料安全

補齊 Apps Script 與資料表契約文件，測試失敗回復、離線狀態及跨裝置同步。

第三階段 · 未完成功能

依使用優先順序完成 COLLECTION、新增捷徑及其他佔位功能。

持續工作 · 品質

每次改動驗證桌面／手機、中英文、三種主題、缺圖、長文字及 API 失敗情境。

文件化

將後端部署、Sheet 欄位、狀態值、快取鍵與測試方式逐步加入專案文件。

版本紀錄

完成改動後直接更新本手記，讓架構說明、開發規則、待辦狀態與程式現況保持一致。

建議驗收矩陣

  • 桌面及手機：六個主頁、所有子分頁、重新整理後狀態還原、三種主題、中英文、長文字與缺圖。
  • 共用 UI：表單開關、ESC、取消、儲存、捲動鎖定、焦點管理與觸控操作。
  • 資料流程：載入中、空資料、API 失敗、離線快取、異動後重新載入；寫入時使用可辨識的測試資料與適當環境。
  • 資料異動：同步確認讀取、正規化、寫入、快取及 UI 更新，保留既有 ID 與狀態值。
